# 2024 S1：AVL 最少节点测试

正式作答文件：**AVLTreeTest.java**。原题要求见本目录README或测试文件注释。

正式答案用 **1棵树，共7个插入节点**。`data()` 是编号0和固定前序；`createTree(0)` 使用题目给的 `createTreeNode`，每次都接收 `insert` 返回的新根。

| 插入顺序 | 当前前序 | 本次旋转 |
|---|---|---|
| 1 | 1 | 无 |
| 7 | 1,7 | 无 |
| 2 | 2,1,7 | RL |
| 3 | 2,1,7,3 | 无 |
| 4 | 2,1,4,3,7 | LR |
| 6 | 4,2,1,3,7,6 | RR |
| 5 | 4,2,1,3,6,5,7 | LL |

最终expected：`List.of(4,2,1,3,6,5,7)`。

### 辅助类怎么用

`ExpectedCalculator.java` 只保留简单入口：修改main里的 `numbers` 数组，用普通for循环逐个插入，再打印前序和expected。

正确参考树及旋转核查放在 `AVLVerification.java`，计算器调用其中的参考树。日常算expected只看ExpectedCalculator即可。`AVLVerification` 的 `--search` 入口保留了原来的穷举核查，供自动验证使用。

已验证在**覆盖LL/RR/LR/RL四类插入旋转**这个目标下，少于7个总节点不够；当前序列恰好7个。它还分别禁用一种旋转，确认最终前序能检出四种错误。仅“执行过四种旋转”不代表最后一定能看出错误，因为后续插入可能补偿前面的错误。

这个最少结论针对明确的四旋转覆盖目标，**不是对全部隐藏实现、全部任意缺陷或官方最优评分的证明**。

### 为什么运行原测试会红

题目自带 `SampleAVLTree` 没有实现平衡，本答案保留它不变。`LocalValidation.java` 用同一份正式测试确认：正确参考树通过，原样例失败。不要为使样例变绿而把expected改成普通BST的前序。

## 直接运行

在本题文件夹打开终端：

```bash
python3 ../run_all.py --only 03 --helpers
```

也可以在已配置Java依赖的IDE中打开 `ExpectedCalculator.java`，点击main旁的Run。修改main中的参数、普通变量或数组，重跑获取expected，再把**确定的数值/布尔值/异常类型**写回正式测试。辅助类不属于考试提交文件，不要直接多交；正式答案不依赖辅助类计算expected。

统一脚本把编译产物放在临时目录，不会把.class或XML运行输出混进题目文件夹。若直接编译，请保留本题原package结构和JUnit版本。
